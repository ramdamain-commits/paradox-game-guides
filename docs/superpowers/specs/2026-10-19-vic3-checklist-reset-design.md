### 章立て

時期の区切りは、技術の時代定義（`common/technology/eras/00_eras.txt`）のコメントにある年に合わせる。era_2 = 1836〜1861、era_3 = 1862〜1886、era_4 = 1887〜1911、era_5 = 1911〜1936（era_1 は開始前の技術）。時代はゲームの経過年ではなく技術の段階なので、章見出しには年を書き、時代名は補足として添える（時代の日本語名はローカライズで確かめてから書く。見つからなければ時代名は書かない）。終盤は era_4 と era_5 をまとめる。

| 章 | 内容 | チェック |
|---|---|---|
| 冒頭 | 対象パッチ・最終確認日・DLC 前提の一文 | — |
| 1. 開始直後（ポーズ中にやること） | 初期設定。10項目以内 | あり |
| 2. 序盤（1836〜1861） | 財政の安定 → 建設の回し方 → 最初の法改正 | あり |
| 3. 中盤（1862〜1886） | 産業化・市場と貿易・政治改革・勢力拡大 | あり |
| 4. 終盤（1887〜） | 列強の地位の維持、崩れやすい点（急進派・財政・戦争）の予防 | あり |
| 5. 定期ルーチン `{.routine}` | グループ分けは5章で決める。目安は「毎年／法律が成立したとき／新しい技術の時代に入ったとき／外交プレイ（戦争）の前と後」 | あり（グループ単位でリセット） |
| 6. 困ったとき | 症状 → 見る場所 → 打ち手（1症状3行） | なし |
| 7. 判断の目安 | 本文の判断に使う数値だけの表。全行に出典 | なし |
| 8. 用語 | このページに出る語のみ。`vic3/localization-reference.md` へリンク | なし |
| 9. 出典 | スクリプトとコミュニティ情報を分けて記載 | なし |

2〜4章の小見出しの立て方（何を軸に並べるか）は書き手に任せる。上の「内容」欄は目安であり、スクリプトと公式ヒントを調べた結果に合わせて変えてよい。

### 載せないもの

- 国別・文化別・政体別の攻略（日本の明治維新 JE、ドイツ統一などの固有ジャーナル）
- 過去パッチとの差分の履歴（1.14 オープンベータ1つだけを書く）
- プレイスタイル別の戦略論、仕組みの長い解説

### 分量の上限（EU5 と同じ）

- チェック項目: 100以内（1〜5章の合計）
- 文字数: `[src:]` マーカーを除いた本文で20,000字以内（除去範囲は `\[src:[^\]]*\]`）
- 1項目: 行動1行＋「なぜ」1行まで

## 3. Markdown 書式

EU5 の設計書3章と同じ。冒頭行だけ VIC3 用に置き換える。

```markdown
# VIC3 プレイ中チェックリスト
> 対象パッチ: 1.14 オープンベータ（release/1.14.5・ビルド 25629520）・変動注意 ／ 最終確認日: YYYY-MM-DD
```

- 信頼性マーカーは repo の `CLAUDE.md`「信頼性マーカー」節に従う。「（公式の説明）」（ゲーム内のヒント・チュートリアル・用語説明だけが根拠の記述）も EU5 と同じ意味で使う。VIC3 ではチュートリアル（`common/tutorial_lessons/`・`tutorial_l_japanese.yml`）と用語説明（`concepts_l_japanese.yml` の `concept_*_desc`）が主な対象
- `[src:]` の書式は repo の `CLAUDE.md` に従い、スクリプトは `ファイル名:行番号`、ローカライズは `ファイル名, キー` にする。行番号はビルドが変わるとずれるので、ビルドが変わったら照合し直す
- 訳語は本文に書く前に `concept_*` キーで確かめる（例: Authority = `concept_authority` = 「権力」、Bureaucracy = 「行政力」、Great Power = 「列強」）

## 4. `checklist.html`

変更しない。VIC3 のチェックリストは `checklist.html?file=vic3/vic3-play-checklist.md` で開く。章番号の前提（チェックは1〜5章、進捗バーは1〜4章、`{.routine}`）は EU5 と同じ書式を守ることで満たす。保存キーはファイルパスごとに分かれる（`checklist:<file>`）ので、EU5 のチェック状態とは混ざらない。

確かめること: VIC3 のファイルで開いて、EU5 の設計書4章の HTML 確認項目（再読込でチェックが残る・リセット・出典トグル・幅375px・ダークモード）が通ること。加えて、EU5 のチェック状態が VIC3 側の操作で消えないこと。

## 5. `scripts/check_checklist.py` の改修

| 変更 | 内容 |
|---|---|
| ゲームの自動選択 | Markdown のパスの最初のフォルダ名で既定のゲームディレクトリを選ぶ。`eu5/` → `Europa Universalis V/game`、`vic3/` → `Victoria 3/game`。それ以外のフォルダで `--game-dir` が無ければ、終了コード2でエラーにする。`--game-dir` を指定したときはそちらを優先する |
| 使い方の表示 | 冒頭の docstring と `--help` に VIC3 の例を足す |
| テスト | `tests/test_check_checklist.py` に、パスからの自動選択（eu5／vic3／不明なフォルダ／`--game-dir` 優先）の4ケースを足す。ディレクトリの有無で結果が変わらないよう、選択ロジックは関数に分けて単体で確かめる |

チェック内容（id・6章以降の項目・上限・`[src:]` の実在・冒頭2項目）は EU5 と同じで、変えない。`[src:]` の実在確認はファイル名だけで照合するので、VIC3 のように同じ名前のファイルが複数のフォルダにある場合は「どれか1つにあれば通る」ことに注意する（数値の裏付けは別途レビューで行う）。

コミット前に必ず次を通す。

```
python scripts/check_checklist.py vic3/vic3-play-checklist.md
python -m unittest discover -s tests
```

## 6. 中身の検証

- 書く前に `buildid` と `caligula_branch.txt` を確かめ、冒頭に書く
- 数値はすべて 1.14 オープンベータのスクリプトで裏付けを取る。旧ガイド（日本・プロイセン）の数値や `[src:]` は、そのまま写さない（1.13.8 以前の値で、`CLAUDE.md` の「前セッションのマーカーも誤りうる」に当たる）。旧ガイドは「何を書くべきか」の発想のもととして git 履歴から読むのはよい
- 1.14 で更新されたファイルが多い領域（`war_goal_types`・`journal_entries`・`treaty_articles`・`static_modifiers`・`interest_groups`・`defines`）に関わる項目は、特に現物で確かめる
- 完成後に3名のレビュー（熟練者・プレイヤー・テクニカルライター）を行う。レビューでは `[src:]` 全件の実在と主要な数値を照合する
