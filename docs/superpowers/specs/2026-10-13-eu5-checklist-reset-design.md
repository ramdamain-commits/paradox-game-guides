# EU5 攻略リセット：プレイ中チェックリスト 設計書

- 作成日: 2026-10-13
- 対象: `paradox-game-guides` の EU5 部分のみ（VIC3・CK3 は変更しない）

## 1. 背景と目的

既存の EU5 攻略は12ファイル・約75万字（国別6本＋共通4本＋MOD＋用語表）。1本が8〜10万字あり、「どの国でも共通の、基本は何をするんだっけ」がすぐ引けない。テンプレートとして使えないため、ゼロベースで作り直す。

### ユーザーの要件（ブレストで確認済み）

| 項目 | 決定 |
|---|---|
| 目的 | どの国でも使える基本の型（何をいつするか） |
| 使う場面 | プレイ中に横に置く手元チェックリスト |
| 範囲 | 共通のみ。国別ガイドは作らない |
| 出典 | 既存と同じ厳密さ（数値はスクリプトで裏取りし `[src:]` を付ける） |
| 形式 | チェックを入れられる HTML ページ |
| 残す既存ファイル | `eu5/localization-reference.md` のみ |
| 対象パッチ | **1.4 オープンベータ**（Steam のベータブランチ `1.4-open-beta`、ビルド 25905365、2026-10-14 に 25606497 から更新。インストール済み） |

### 対象パッチについて

- ユーザーの指示により、1.4 オープンベータを本文の基準にする。repo の `CLAUDE.md` にある「公開ベータは差分セクションに追記し、安定版を基準に保つ」ルールは、このチェックリストには適用しない（`CLAUDE.md` に例外として明記する）
- 冒頭の対象パッチ欄は「1.4 オープンベータ（ビルド 25905365）・変動注意」と書く
- ベータは Steam が自動更新するため、作業の最初と最後にビルド番号を確認する。途中で変わっていたら、`[src:]` の実在確認と数値の裏取りをやり直す
- 1.4 の安定版が出たときの再検証は今回の範囲外（別作業）

### 前提（ユーザー未確認の仮定）

- 読み手は「EU5を一通り遊んだが、間が空くと忘れる」レベル。仕組みの解説は最小限にし、行動を中心に書く
- 利用者は本人1人。チェック状態はブラウザ（localStorage）保存で足りる

## 2. 構成

### 方式

Markdown を正本とし、HTML がそれを読み込んでチェックリストとして描画する（ブレストの案1）。

| ファイル | 役割 |
|---|---|
| `eu5/eu5-play-checklist.md` | 中身の正本（新規） |
| `checklist.html` | Markdown を読み込みチェックリスト化する汎用ビューア（新規・ルート直下） |
| `scripts/check_checklist.py` | 書式と出典の検証スクリプト（新規） |
| `eu5/localization-reference.md` | 用語の正本（既存・残す） |

### 章立て

時期の区切りはゲーム内の「時代」定義に合わせる（`in_game/common/age/00_default.txt` の `year =`。日本語名はローカライズの `age_*` キー）。伝統1337／ルネサンス1342／発見1437／宗教改革1537／絶対主義1637／革命1737。伝統は5年しかないため、序盤に統合する。

| 章 | 内容 | チェック |
|---|---|---|
| 冒頭 | 対象パッチ・最終確認日 | — |
| 1. 開始直後（ポーズ中にやること） | 初期設定。10項目以内 | あり |
| 2. 序盤：伝統〜ルネサンス（1337〜1437） | 安全確保 → 安定化 → 拡大開始 | あり |
| 3. 中盤：発見〜宗教改革（1437〜1637） | 本格拡大・国家ランク昇格・進歩の取り方 | あり |
| 4. 終盤：絶対主義〜革命（1637〜） | 維持と仕上げ、崩れやすい点の予防 | あり |
| 5. 定期ルーチン `{.routine}` | 毎年／10年ごと／時代が変わったとき／戦争の前と後 | あり（グループ単位でリセット） |
| 6. 困ったとき | 症状 → 見る場所 → 打ち手（1症状3行） | なし |
| 7. 判断の目安 | 本文の判断に使う数値だけの表。全行に出典 | なし |
| 8. 用語 | このページに出る語のみ。`localization-reference.md` へリンク | なし |
| 9. 出典 | スクリプトとコミュニティ情報を分けて記載 | なし |

### 載せないもの

- 国別・政体別・宗教別の攻略
- 過去パッチとの差分の履歴（対象パッチ1つのみを書く）
- プレイスタイル別の戦略論、仕組みの長い解説

### 分量の上限

- チェック項目: 100以内（1〜5章の合計）
- 文字数: `eu5-play-checklist.md` の `[src:]` マーカーを除いた本文で20,000字以内（マーカーは `checklist.html` では既定で非表示のため。除去範囲は `\[src:[^\]]*\]`）
- 1項目: 行動1行＋「なぜ」1行まで

## 3. Markdown 書式ルール

```markdown
# EU5 プレイ中チェックリスト
> 対象パッチ: 1.x.x ／ 最終確認日: YYYY-MM-DD

## 1. 開始直後（ポーズ中にやること）
- [ ] 〇〇を△△に設定する {#start-tax}
  - なぜ: □□が序盤の収入を左右するため [src: xxx.txt, identifier]

## 5. 定期ルーチン {.routine}
### 毎年
- [ ] 収支が黒字か確認する {#yearly-balance}
```

- チェック項目は `- [ ] 本文 {#id}`。id は `^[a-z0-9]+(-[a-z0-9]+)*$`、ファイル内で一意。チェック状態は id に結び付くため、文言の修正や並べ替えでは消えない。id は一度付けたら変えない
- 「なぜ」は子の箇条書き1行で、`- なぜ: ` で始める。任意
- `[src: ファイル名, 識別子]` などの信頼性マーカーは、repo の `CLAUDE.md`「信頼性マーカー」節にそのまま従う
- `## ... {.routine}` を付けた章では、直下の `###` が1つのリセット単位になる
- `## 6.` 以降はチェックボックスを使わない（使っても検証スクリプトでエラーにする）

## 4. `checklist.html` の挙動

- **読み込み**: `checklist.html?file=<repo相対パス>`。`file` は `.md` で終わり、`..` を含まないものだけ受け付ける。CDN の marked で Markdown を解析する（`viewer.html` と同じライブラリ。バージョンは完全指定にする）
- **描画**
  - `- [ ] ... {#id}` をチェックボックス付きの項目に変換する。`{#id}` は表示しない
  - 1〜5章の `##` と、5章の `###` は折りたたみ式。見出しに `[済/全]` を表示する
  - 上部の進捗バーは1〜4章の項目だけを数える（ルーチンは数えない）
  - 「なぜ」行は小さめの灰色で表示する
  - `[src: ...]` は既定では隠し、上部の「出典を表示」トグルで表示を切り替える。`（コミュニティ知見）` `（未検証）` は常に表示する
  - 6章以降は通常の Markdown として描画する
- **保存**: localStorage に `{ checked: {id: true}, open: {sectionKey: bool}, showSrc: bool }` を保存する。キーは `checklist:<file>`。読み書きはすべて try/catch で囲み、保存できない環境でも表示と操作はできるようにする。Markdown に存在しない id の保存値は無視する
- **リセット**: 「新しいプレイを始める」は全チェックを消す。ルーチンのリセットボタンは、そのグループの id だけを消す。どちらも `confirm()` を出す
- **見た目**: 幅375pxでも横スクロールが出ない。`prefers-color-scheme` でダークモードに対応する。`viewer.html` への「Markdown で読む」リンクを置く
- **エラー表示**: Markdown を取得できないとき、または `file` が不正なときは、本文の位置にメッセージを出す

## 5. 検証

### `scripts/check_checklist.py <md>`

違反があれば終了コード1で、違反を行番号つきで一覧表示する。

1. 1〜5章のチェック項目すべてに `{#id}` があり、id の形式が正しく、重複がない
2. 6章以降にチェック項目がない
3. 項目数が100以内、文字数が `[src:]` マーカーを除いた本文で20,000以内（マーカーは `checklist.html` では既定で非表示のため）
4. `[src: X ...]` の X が EU5 インストール版の `game/` 配下に実在する（ファイル名で検索。`Patch_*` `wiki` 等の URL 系ショートマーカーは対象外）
5. 冒頭に「対象パッチ」と「最終確認日」がある

**ハーネス自体の確認**: 壊したデータ（id 抜け・id 重複・不正な id・6章以降のチェック項目・存在しない src ファイル・上限超過）を各ケースで検出できることを、`unittest`（標準ライブラリ。pytest は未導入のため）で確かめる。壊したデータはテスト内の文字列で作る。正しいデータとして `tests/fixtures/checklist_sample.md` を置き、通ることを確かめる（このファイルは HTML の動作確認にも使う）。インストール版を参照する4番は、ファイル名の集合を引数で差し替えられるようにし、テストでは固定の集合を使う。

### HTML

ローカルで `python -m http.server` を起動し、ブラウザで次を確かめる。

- チェック → 再読込しても残る
- 全リセット・ルーチンリセットがそれぞれ対象だけを消す
- 出典トグルが効く
- 幅375pxで崩れない
- ダークモードで読める
- `file` が不正・存在しないときにメッセージが出る

### 中身

- 書く前に、インストール版のビルド番号（`appmanifest_3450310.acf` の `buildid`）と 1.4 ベータの版番号を確定し、冒頭に記載する
- 数値はすべてスクリプトで裏取りする（repo の `CLAUDE.md` の規則どおり）
- 完成後に3名のレビュー（熟練者・プレイヤー・テクニカルライター）を行う
